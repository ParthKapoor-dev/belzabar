Usage: wi-impl ad create --spec <FILE> [--category <CATEGORY>] --env <env> [flags]

Create a new DRAFT method from a spec through the V2 route
(POST /chain/v2 without a uuid). Returns the new uuid.

Compact spec (wi-impl expands it to the full V2 body with UI defaults):
  {
    "name": "orders.list", "category": "Sandbox",
    "summary": "…", "description": "…",
    "inputs":    ["id", {"key": "limit", "type": "INTEGER", "required": true,
                          "default": 10, "description": "…"}],
    "variables": ["rows"],
    "outputs":   ["rows", {"key": "count", "type": "INTEGER"}],
    "steps": [
      {"sql": "SELECT … WHERE id = '#{id}'", "account": "APP-RDS",
       "outputs": {"rows": "flatData[]"}, "when": "#{id} ne null"},
       // flatData[] = the rows as an array of OBJECTS [{col: v}, …]
       // output keys cannot be indexed (flatData[0].col is refused): reduce
       // in a next step, e.g. echo "Input": "#{rows[0].col}"
      {"service": "Helpers.Legacy/echo", "inputs": {"Input": "#{rows.size()}"},
       "outputs": [{"key": "response", "as": "count"}]},
      {"codeFile": "step3.js", "outputs": ["a", "b"], "exit": {"onFailure": false}}
    ]
  }
  Step keys: service "Svc/method" | code | codeFile | sql | sqlFile (paths
  relative to the spec), inputs {key: value, "body.nested": value}, outputs
  ["key"] | [{key, as, var, type, elementToRetrieve}] | {as: key}, when,
  exit {onFailure, code, message}, exitIf {when, code, message},
  loop {over} | {times} | {while} | {from, to, by} (+counter, parallel,
  threads), account (db_service: an id or nickname; it may be omitted only
  when the service has exactly one account on the env — e.g. one env has
  several, and then AD_SPEC_INVALID lists them as id=nickname; see
  `wi-impl ad child-info db_service select` lists them), description,
  language, async. `sql` alone picks db_service data.read/add/update/delete
  from the verb. Service input/output keys, accounts and services are checked
  online against the callee contract (unknown ones are refused: the server
  would drop them). Custom-code outputs get elementToRetrieve when there are
  several. See `wi-impl ad save --help` for the same format in structural edits.

A V2 method body (e.g. the V2 `data.raw` of `wi-impl ad fetch`) or a subset of it
works too: server-owned keys (uuid, ids, metadata state/version/service,
changelogs, permissions…) are dropped and listed in `dropped`; step ids and
method-level uuids are minted by the server. Raw and compact steps can mix.

Flags:
  --spec <FILE>         Spec file (compact, or a V2 body/subset). (required)
  --category <CATEGORY> Target category: name, chain-category id, or uuid. Required
                        unless the spec has "category" (both must agree).
                        Core/shared categories (Helpers.*, Database.*, Cache.*,
                        Email.*, Expertly.*, Web Socket, system services) are
                        refused with AD_CATEGORY_PROTECTED.
  --dry-run             Expand + validate only; create nothing. Returns
                        {dryRun, valid, body, validation{errors, warnings}}.
  --yes, -y             Skip the confirmation prompt (required with --llm).
  --no-validate         Skip the validator. Logged loudly; not recommended.
  --strict              Validator warnings block the create too.
  --dry-run-compile     Also run the online checks (server compile dry run:
                        POSTs the executing /chain/test route with every step
                        gated off, so --dry-run then counts as a write).
  --help, -h            Show this help message.

Global Flags:
  --env <name>          Target environment. Always required, --dry-run too:
                        the dry run reads the target env, so it never falls
                        back to the default env (ENV_REQUIRED_FOR_WRITE).
  --llm                 Output structured JSON envelope for scripting/LLM use.

Platform trap: a new draft stores no input testValues (wi-impl cannot set them),
so the AD designer's Test dialog reports "Mandatory fields are not filled" for
its required inputs until they are entered there; the create warns and names
them. 'wi-impl ad test' takes the values as inputs instead.

Errors: MISSING_CATEGORY, AD_SPEC_UNKNOWN_KEY, AD_SPEC_INVALID,
AD_SPEC_NOT_APPLIED (key/service/account the server would drop or reject;
method inputs/outputs/variables get the same checks as `ad save` set-input:
testValue and a variable's BASE_64 encodingType are refused, unknown keys too),
CATEGORY_NOT_FOUND, AD_CATEGORY_PROTECTED, AD_VALIDATION_FAILED,
AD_METHOD_EXISTS (name taken in the category), AD_SAVE_REJECTED (server
message), AD_SAVE_VERIFY_FAILED (a value sent does not read back).

Data: {uuid, name, state, version, category{chainCategoryId,
chainCategoryUuid, name}, stepCount, dropped[], validation{skipped, warnings,
layersRun}}.

Examples:
  wi-impl ad create --spec method.json --dry-run --env <env> --llm
  wi-impl ad create --category Sandbox --spec method.json --env <env>
  wi-impl ad create --category 42 --spec method.json --env <env> --yes --llm
