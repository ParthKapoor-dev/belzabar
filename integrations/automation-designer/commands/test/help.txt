Usage: wi-impl ad test <UUID> [flags]

Execute an Automation Designer method for testing and inspection.
This really runs the chain (SQL steps commit, HTTP steps call out), so it
requires an explicit --env.

Arguments:
  <UUID>                The UUID of the method to test (usually the draft).

Flags:
  --inputs <FILE|JSON>  Input values: a JSON file, or an inline JSON object
                        ('{"name":"World"}'), as `ad run` takes its payload.
  --input <KEY=VALUE>   One input value (repeatable), applied on top of --inputs
                        or --case. Typed by the method's input type (non-text
                        types parse as JSON). An unknown key is INVALID_INPUT.
                        Without --inputs/--input/--case the values are prompted
                        for (refused with --llm).
  --case <FILE>         Take the inputs AND the expectations from a test-case file
                        (`wi-impl ad test-case export` format, or a UI test-case body):
                        every `{output, op, expected}` assertion is checked locally.
                        Cannot be combined with --inputs.
  --cases <FILE>        Run the method once per case in FILE: a JSON array, or JSONL
                        (one object per line), of {name?, inputs?, expect?[]} where
                        expect uses the --expect syntax. --input and --expect apply
                        to every case. Every case is a REAL execution (N cases, N
                        sets of side effects), so it confirms first, showing the
                        case count (--yes, required with --llm). Every row's inputs
                        are checked before anything runs. Prints one row per case;
                        exit 1 with AD_TEST_CASES_FAILED when any case fails.
                        Cannot be combined with --inputs, --case or
                        --compare-published.
  --expect <OUT=VALUE>  Check a method output after the run (repeatable). Operators:
                        = != ~= (contains) > < >= <=; `out.a[0]=x` looks inside JSON.
                        The value is JSON when it parses, else text; quote it
                        ('42') to compare as a string. Any failure exits 1 with
                        AD_TEST_EXPECTATION_FAILED.
  --compare-published   Also run the same inputs against the published copy (a draft's
                        referenceId, or the draft of a published uuid) and diff every
                        output. This EXECUTES TWICE — both runs have real side effects,
                        one through the production body — so it asks for confirmation
                        (--yes, required with --llm). Expectations and the draft run's
                        status decide the exit code.
  --yes, -y             Confirm --compare-published's second (published) execution,
                        or the --cases executions.
  --verbose, -v         Show detailed execution trace for each step. (A command
                        flag here: it does not switch on runner debug logging.)
  --raw                 Include raw execution payload in output.
  --help, -h            Show this help message.

Global Flags:
  --env <name>          Set active environment. Required explicitly: this
                        really executes the chain. Any env from `wi-impl envs`.
  --llm                 Output structured JSON envelope for scripting/LLM use.

Notes:
  - Exit 1 with AD_TEST_FAILED when the (draft) execution FAILED, with the
    full data (failedStep, trace); AD_TEST_EXPECTATION_FAILED wins when an
    expectation failed.
  - Posts {category, jsonDefinition, id, uuid, version} to /chain/test with
    testValues set and automationApiId filled on every step (lean chains).
  - Data: outputs {code: value} (every method output), trace, expectations
    {total, passed, failed, results[]}, compare {identical, differences[],
    published{status, outputs}}.
  - With --cases, data is {uuid, cases[{name, pass, status (SUCCESS, FAILED
    or ERROR), outputs, failedStep, expectations[], error?{code, message}}],
    summary{total, passed, failed}}. A case whose run throws (compile error)
    is status ERROR; the other cases still run.
  - Trace rows carry the method's own step descriptions and orderIndex.

Examples:
  wi-impl ad test 4a1b2c3d... --env <env> --inputs ./in.json --expect greetingOut='Hello World'
  wi-impl ad test 4a1b2c3d... --env <env> --input name=World --expect 'greeting=Hello, World' --llm
  wi-impl ad test 4a1b2c3d... --env <env> --case ./cases/greet.ok.1.json --compare-published --yes --llm
  wi-impl ad test 4a1b2c3d... --env <env> --cases ./cases.jsonl --yes --llm
  wi-impl ad test 4a1b2c3d... --env <env> --inputs ./test-data.json --verbose --raw
