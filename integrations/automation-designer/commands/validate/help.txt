Usage: belz ad validate <UUID|FILE> [flags]

Run the pre-save validator over a method's V2 body (read-only).

Arguments:
  <UUID|FILE>           A method uuid (any spelling or AD URL; the V2 body is
                        fetched from --env), a local V2 JSON file (the body you
                        are about to save), or the compact spec `ad create`
                        takes (expanded against --env first, as
                        `create`'s dry run does; data.spec says so). A path or a
                        name ending in .json.

Flags:
  --online              Also check every step against its service contract on
                        --env: input keys (case-sensitive), service names,
                        automationAPIId, account ids (L4).
  --dry-run-compile     Also compile the method on the server with every step
                        switched off (implies --online). Nothing executes; POSTs
                        /chain/test, so --env must be given explicitly. A compile
                        error is AD-COMPILE-001, any other refusal (non-2xx) is
                        AD-COMPILE-002; both are errors.
  --strict              Treat warnings as errors.
  --category <CATEGORY> Category for a compact spec without "category" (name, id
                        or uuid; must agree with spec.category).
  --help, -h            Show this help message.

Global Flags:
  --env <name>          Set active environment (default: WI_IMPL_ENV, else defaultEnv, else the only env).
                        Any env from `belz envs` (configured in ~/.wi-impl/config.json).
  --llm                 Output structured JSON envelope for scripting/LLM use.

Notes:
  - Layers: L1 structure, L2 per step (custom code, SQL, SpEL, loops,
    conditions), L3 reference graph, L4 online. Rule codes are listed in
    integrations/automation-designer/lib/validate/catalogue.ts.
  - Errors exit 1 with AD_VALIDATION_FAILED; data carries {errors, warnings,
    layersRun, notes}. A <uuid> is audited as the stored record: AD-META-001 is
    dropped for a PUBLISHED record and M1 on its existing name is a warning
    (a file is judged as a new body). `ad save` / `ad publish` run the same validator and only block
    on NEW errors (findings already in the fetched draft are warnings).

Examples:
  belz ad validate 4a1b2c3d4e5f60718293a4b5c6d7e8f9 --env acme-dev
  belz ad validate ./method.v2.json --online --env acme-dev --llm
  belz ad validate ./method.v2.json --dry-run-compile --env acme-dev
  belz ad validate ./greet.spec.json --env acme-dev --llm
