Usage: belz ad sql <subcommand> [args] [flags]

Run SQL queries via Automation Designer database services.

Subcommands:
  dbs                 List available database auth configurations.
  run <QUERY>         Execute ONE read statement (SELECT / WITH … SELECT / VALUES /
                      EXPLAIN [ANALYZE] of a read). Anything else — DML, DDL, multiple
                      statements, SELECT INTO, FOR UPDATE, any SpEL '#{…}' (the
                      server evaluates it into the SQL text) — is refused client-side
                      (SQL_NOT_READ_ONLY); use update/insert/modify for writes.
  explain <QUERY>     Show the query plan of ONE read statement (pass it without
                      EXPLAIN). The statement must pass the same read-only gate as
                      run: --analyze really executes it, so DML is always refused.
  update <QUERY>      Execute a SQL write (UPDATE/DELETE) query.
  insert <QUERY>      Execute a SQL INSERT query. Add `RETURNING <key column>` to get
                      the generated key(s) back in generatedValues (one row, or
                      several: generatedKeys lists every returned key row).
  modify <QUERY>      Execute a DDL schema change (ALTER TABLE, CREATE INDEX, etc.).
  tui                 Start an interactive SQL session (can run writes: --env required).

Flags (dbs):
  --raw               Include raw API response.

Flags (run):
  --db <NAME|ID>      Database nickname or ID.
                      Default resolution (every subcommand): --db →
                      environments.<env>.sqlDefaultDb in ~/.belz/config.json →
                      BELZ_SQL_DEFAULT_DB → NSM_Read_DB (exists on NSM only).
                      selectedBy reports which one was used.
  --raw               Include raw operation metadata and execution response.

Flags (explain):
  --analyze           EXPLAIN ANALYZE: execute the statement and report real row
                      counts and timings (timing {planningMs, executionMs}).
  --buffers           Add buffer usage (needs --analyze).
  --format <FMT>      text (default; plan = lines) | json (plan = parsed JSON).
  --db <NAME|ID>      Database nickname or ID (same default resolution as run).
  --raw               Include raw operation metadata and execution response.

Flags (update):
  --db <NAME|ID>      Database nickname or ID.
  --raw               Include raw operation metadata and execution response.
  --yes, -y           Skip the confirmation prompt (required with --llm).

Flags (insert):
  --db <NAME|ID>      Database nickname or ID.
  --raw               Include raw operation metadata and execution response.
  --yes, -y           Skip the confirmation prompt (required with --llm).

Flags (modify):
  --db <NAME|ID>      Database nickname or ID.
  --raw               Include raw operation metadata and execution response.
  --yes, -y           Skip the confirmation prompt (required with --llm).

Flags (tui):
  --db <NAME|ID>      Pre-select database (skips interactive DB prompt).
  --mode <MODE>       Pre-select mode: read | insert | update | modify (skips interactive mode prompt).
  --format <MODE>     Row output format: table (default) | json.
  --timing            Print timing details after each statement.
  --page-size <N>     Rows per page for pagination. (default: 50)
  --no-history        Disable persisted query history for this session.

Flags (all subcommands):
  --v2                Accepted for consistency; SQL runs through V1 (notice printed).

TUI meta commands:
  \q  \h  \status  \db  \use <db>  \mode [read|insert|update|modify]  \history  \clear  \timing  \format [table|json]  \last  \r

  --help, -h          Show this help message.

Global Flags:
  --env <name>        Set active environment (default: defaultEnv, else nsm-dev).
                      use `belz envs` to list all available envs.
                      update/insert/modify/tui are writes: --env must be explicit.
  --llm               Output structured JSON envelope for scripting/LLM use.

Examples:
  belz ad sql dbs
  belz ad sql run "select * from users limit 1"
  belz ad sql run "select * from users limit 1" --db NSM_QA_DB
  belz ad sql explain "select * from users where email = 'x'" --analyze --db NSM_QA_DB
  belz ad sql update "UPDATE users SET status = 'active' WHERE id = 1" --db NSM_Write_DB --env <env>
  belz ad sql insert "INSERT INTO users (name) VALUES ('test') RETURNING id" --db NSM_Write_DB --env <env> --yes
  belz ad sql modify "CREATE INDEX IF NOT EXISTS idx_name ON users(name)" --db NSM_Write_DB --env <env>
  belz ad sql tui --env <env>
  belz ad sql tui --mode insert --db NSM_Write_DB --env <env>
  BELZ_SQL_DEFAULT_DB=NSM_QA_DB belz ad sql run "select now()"
