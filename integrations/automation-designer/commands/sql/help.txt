Usage: wi-impl ad sql <subcommand> [args] [flags]

Run SQL queries via Automation Designer database services.

Subcommands:
  dbs                 List available database auth configurations.
  run <QUERY>         Execute read statements (SELECT / WITH … SELECT / VALUES /
                      EXPLAIN [ANALYZE] of a read, or plain EXPLAIN — no ANALYZE — of
                      an INSERT/UPDATE/DELETE/MERGE, which only plans it and is a safe
                      syntax check). Anything else — DML, DDL, SELECT INTO, FOR
                      UPDATE, any SpEL '#{…}' (the server evaluates it into the SQL
                      text) — is refused client-side (SQL_NOT_READ_ONLY); use
                      update/insert/modify for writes. Several statements: see Batch.
  explain <QUERY>     Show the query plan of ONE statement (pass it without EXPLAIN).
                      The statement can come from --file or stdin too.
                      Plain EXPLAIN also takes INSERT/UPDATE/DELETE/MERGE: it only
                      plans them. With --analyze the statement is really executed, so
                      it must pass the same read-only gate as run (DML is refused).
  tables              List the tables and views (schema, name, type), system schemas
                      left out. --schema <S> for one schema, --like <PART> to filter
                      names (ILIKE; without '%' it means "contains").
  describe <TABLE>    The columns of one table or view (<table> or <schema>.<table>):
                      name, type, nullable, default, primaryKey. A name that does not
                      exist is SQL_TABLE_NOT_FOUND with the similar names; one in
                      several schemas is SQL_TABLE_AMBIGUOUS (pass schema.table).
  update <QUERY>      Execute a SQL write (UPDATE/DELETE; WITH … UPDATE/DELETE) query;
                      returns rowsAffected.
  insert <QUERY>      Execute a SQL INSERT query. Add `RETURNING <key column>` to get
                      the generated key(s) back in generatedValues (one row, or
                      several: generatedKeys lists every returned key row).
  modify <QUERY>      Execute a DDL schema change (ALTER / CREATE / DROP / TRUNCATE /
                      COMMENT / GRANT / REVOKE / REINDEX / REFRESH / CLUSTER).
                      update, insert and modify also return executedAt: when
                      the statement was sent (ISO-8601 UTC, this machine's
                      clock), to find the rows it touched by their
                      updated_at / created_at stamps (allow for clock skew).
  tui                 Start an interactive SQL session (can run writes: --env required).
                      Human use only: with --llm it fails SQL_TUI_UNSUPPORTED_IN_LLM.

Input (run, explain, update, insert, modify):
  <QUERY> is the SQL as one argument, or '-' to read it from stdin. --file <path>
  reads it from a file (--file - is stdin too). A file or stdin has no
  argument-length limit. Pass the argument or --file, not both
  (SQL_QUERY_AND_FILE); neither is MISSING_SQL_QUERY.

Batch (run, update, insert, modify):
  Several ';'-separated statements (from any input) run in ONE call: the
  database and the operation load once, then each statement is sent in order.
  Every statement passes its gate before anything is sent (the error names it:
  "Statement 2 of 5: …"). data is {batch: true, statementCount, okCount,
  failedCount, results: [{index, query, ok, rows/rowCount | rowsAffected |
  generatedValues, executedAt (writes), error?}]}. Reads all run (4 at a time; results in input
  order); writes run in order and stop at the first failure (the rest are
  notRun: true). Any failure: SQL_BATCH_FAILED, with every
  result still in data. One statement keeps the single-statement shape.

Write checks (update, insert, modify):
  The statement is checked before it is sent: an empty or comment-only one is
  SQL_EMPTY_STATEMENT, one of another kind (e.g. modify "UPDATE …") is
  SQL_WRONG_STATEMENT. modify refuses a DELETE: 'sql update' runs it and returns
  rowsAffected.

Errors (run, explain, update, insert, modify):
  A statement the database refuses fails with SQL_QUERY_FAILED (run/explain) or
  SQL_<UPDATE|INSERT|MODIFY>_QUERY_FAILED; error.message holds the database's own
  message (e.g. 'column "x" does not exist'), details.query the query.
  A stopped or restarting environment (HTTP 502/503/504) is ENV_UNAVAILABLE, not a
  database error: run the statement again once the environment is up.

Bind parameters (run, explain, update, insert):
  The server reads a lone '?' and a ':name' (also the ':6' of arr[1:6]) in
  run/explain/update/insert as bind parameters and fails, so they are refused
  before sending (SQL_PARAMETER_MARKER). Write the jsonb operators doubled
  ('??', '??|', '??&'; or jsonb_exists(col, 'key') / col->'key' IS NOT NULL) and
  a slice with a space after the colon: arr[1: 6]. '::' casts are fine.

Flags (dbs):
  --raw               Include raw API response.

Flags (run):
  --file <PATH>       Read the SQL from a file ('-' = stdin) instead of the argument.
  --db <NAME|ID>      Database nickname or ID.
                      Default resolution (every subcommand): --db →
                      environments.<env>.sqlDefaultDb in ~/.wi-impl/config.json →
                      WI_IMPL_SQL_DEFAULT_DB (no built-in name: without them,
                      pass --db; SQL_DEFAULT_DB_NOT_FOUND).
                      selectedBy reports which one was used.
  --raw               Include raw operation metadata and execution response.

Flags (explain):
  --file <PATH>       Read the statement from a file ('-' = stdin).
  --analyze           EXPLAIN ANALYZE: execute the statement and report real row
                      counts and timings (timing {planningMs, executionMs}).
  --buffers           Add buffer usage (needs --analyze).
  --format <FMT>      text (default; plan = lines) | json (plan = parsed JSON).
  --db <NAME|ID>      Database nickname or ID (same default resolution as run).
  --raw               Include raw operation metadata and execution response.

Flags (tables):
  --schema <S>        Only this schema (it may be a system schema).
  --like <PART>       Only names matching (ILIKE; no '%' = contains).
  --db <NAME|ID>      Database nickname or ID (same default resolution as run).

Flags (describe):
  --db <NAME|ID>      Database nickname or ID (same default resolution as run).

Flags (update):
  --file <PATH>       Read the SQL from a file ('-' = stdin) instead of the argument.
  --db <NAME|ID>      Database nickname or ID.
  --raw               Include raw operation metadata and execution response.
  --yes, -y           Skip the confirmation prompt (required with --llm).

Flags (insert):
  --file <PATH>       Read the SQL from a file ('-' = stdin) instead of the argument.
  --db <NAME|ID>      Database nickname or ID.
  --raw               Include raw operation metadata and execution response.
  --yes, -y           Skip the confirmation prompt (required with --llm).

Flags (modify):
  --file <PATH>       Read the SQL from a file ('-' = stdin) instead of the argument.
  --db <NAME|ID>      Database nickname or ID.
  --raw               Include raw operation metadata and execution response.
  --yes, -y           Skip the confirmation prompt (required with --llm).

Flags (tui):
  --db <NAME|ID>      Pre-select database (skips interactive DB prompt).
  --mode <MODE>       Pre-select mode: read | insert | update | modify (skips interactive mode prompt).
  --format <MODE>     Row output format: table (default) | json.
  --timing            Print timing details after each statement.
  --page-size <N>     Rows per page for pagination. (default: 50)
  --no-history        Disable persisted query history for this session.

TUI meta commands (tui):
  \q  \h  \status  \db  \use <db>  \mode [read|insert|update|modify]  \history  \clear  \timing  \format [table|json]  \last  \r

Flags (all subcommands):
  --help, -h          Show this help message (with a subcommand: only that
                      subcommand's part, e.g. wi-impl ad sql update --help).

Global Flags:
  --env <name>        Set active environment (default: WI_IMPL_ENV, else defaultEnv, else the only env).
                      use `wi-impl envs` to list all available envs.
                      update/insert/modify/tui are writes: --env must be explicit.
  --llm               Output structured JSON envelope for scripting/LLM use.

Examples:
  wi-impl ad sql dbs
  wi-impl ad sql run "select * from users limit 1"
  wi-impl ad sql run "select * from users limit 1" --db QA_DB
  wi-impl ad sql run --file checks.sql --db QA_DB
  cat checks.sql | wi-impl ad sql run - --db QA_DB
  wi-impl ad sql update --file fix.sql --db WRITE_DB --env <env> --yes
  wi-impl ad sql explain "select * from users where email = 'x'" --analyze --db QA_DB
  wi-impl ad sql explain "UPDATE users SET status = 'x' WHERE id = 1" --db QA_DB
  wi-impl ad sql tables --like user --db QA_DB
  wi-impl ad sql describe public.users --db QA_DB
  wi-impl ad sql update "UPDATE users SET status = 'active' WHERE id = 1" --db WRITE_DB --env <env>
  wi-impl ad sql insert "INSERT INTO users (name) VALUES ('test') RETURNING id" --db WRITE_DB --env <env> --yes
  wi-impl ad sql modify "CREATE INDEX IF NOT EXISTS idx_name ON users(name)" --db WRITE_DB --env <env>
  wi-impl ad sql tui --env <env>
  wi-impl ad sql tui --mode insert --db WRITE_DB --env <env>
  WI_IMPL_SQL_DEFAULT_DB=QA_DB wi-impl ad sql run "select now()"
