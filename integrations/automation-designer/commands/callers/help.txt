Usage: wi-impl ad callers <UUID> [flags]

List the AD methods (and with --pd the PD pages / components) that call a
method — the backward-compatibility check before changing its contract.
Read-only.

AD methods are matched env-wide through the cached method index (step refs by
automation-API uuid / numeric id). Steps the index only knows by their numeric
automationId are resolved by reading method bodies (cached per method version)
for the target's own category, the --category list, or every category with
--all; `coverage.unscannedMethods` counts methods left unresolved elsewhere.
A body the V2 route refuses (HTTP 400 on some old methods) is read through
V1 instead, as `wi-impl ad show` does.
A draft and its published copy are both reported when both call it, each
with its own step numbers. A caller row names its other copy
(`counterpartUuid`) and says whether the two copies' steps differ
(`draftDiffers`: callees, step descriptions, input keys, outputs or step
order); both are omitted when the other copy could not be read.

The index is rebuilt when it is more than 24 h old (or partial and more than
15 min old). Methods wi-impl itself saved, created, published, restored or
deleted since the index was built are re-read. Methods created or edited in
the AD UI since then are missed until --refresh; `coverage.complete` is true
only for a fresh, complete index with nothing left unresolved, and
`coverage.skippedCategories` lists categories whose listing failed.

Arguments:
  <UUID>                The target method's uuid (draft or published) or AD URL.

Flags:
  --category <a,b>      Also resolve every step in these categories (names).
  --all                 Resolve every step in every category (slow the first
                        time: one read per method; cached afterwards).
  --pd                  Also scan PD pages (drafts and published pages, each
                        with its own calls) and components for httpRequests
                        executing the method (3 large list reads, cached 1 h).
                        A failed listing never fails the command: the last
                        complete PD index (kept 7 days) is used (pd.source
                        stale), else the listings that worked
                        (pd.failedListings), else pd.source unavailable with
                        pd.error; a warning says which.
  --refresh             Rebuild the method index (and the PD reference index).
  --help, -h            Show this help message.

Global Flags:
  --env <name>          Set active environment (default: WI_IMPL_ENV, else defaultEnv, else the only env).
                        Any env from `wi-impl envs` (configured in ~/.wi-impl/config.json).
  --llm                 Output structured JSON envelope for scripting/LLM use.

Examples:
  wi-impl ad callers 48e5d8bec3f5d7b5d689914d3b36aed8
  wi-impl ad callers 48e5d8bec3f5d7b5d689914d3b36aed8 --category Schools --pd --llm
  wi-impl ad callers 48e5d8bec3f5d7b5d689914d3b36aed8 --all --refresh

Errors: CATEGORY_NOT_FOUND (--category names a category the index lacks),
AD_INDEX_FETCH_FAILED (the category listing failed while building the index);
details carry {path, status}. A failed --pd listing is not an error (see --pd).
