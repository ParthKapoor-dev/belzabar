wi-impl ad save <file> --uuid <uuid> --env <env>  :->  Save a JSON overlay onto the method's draft via V2: name/summary/description/scope, parsedSteps[] leaf edits, and ops[] (add-step/remove-step/move-step/update-step with compact steps, incl. set.service to retarget a step; set-/remove-input|variable|output); step numbers = fetched positions; validated, freshness-checked, verified on re-read, compiled cache evicted
wi-impl ad save [file] --uuid <uuid> --env <env> --sql-file <N=path>  :->  Replace step N's SQL with the file's text (repeatable; stored in the step's encoding)
wi-impl ad save [file] --uuid <uuid> --env <env> --code-file <N=path>  :->  Replace step N's custom code with the file's text (repeatable; stored in the step's encoding)
wi-impl ad save <file> --uuid <uuid> --env <env> --dry-run  :->  Plan + validate only, write nothing (--env still required: it reads the target draft): applied ops, every changed field before/after, new step order (new steps new#1, new#2…), outputs the method returns, valid, validator errors/warnings, testValuesAtRisk
wi-impl ad save <file> --uuid <uuid> --env <env> --yes --llm  :->  Non-interactive save (--yes is required in --llm mode)
wi-impl ad save <file> --uuid <uuid> --env <env> --strict  :->  Validator warnings block the save too
wi-impl ad save <file> --uuid <uuid> --env <env> --dry-run-compile  :->  Also run the online validator checks (server compile dry run)
wi-impl ad save <file> --uuid <uuid> --env <env> --no-validate  :->  Skip the validator (logged loudly; not recommended)
wi-impl ad save <file> --uuid <uuid> --env <env> --keep-case-changes  :->  Leave the test cases as the server rewrote them on the save (default: wi-impl puts them back and reports data.testCases)
