Usage: wi-impl ad publish <UUID> --note "<what changed>" --env <env> [flags]

Publish a draft: promotes the current draft contents to the published version
of the same method. Returns the published UUID and a version-sync summary.

The draft is validated first (the server publishes broken methods with 200).
A change note is MANDATORY: wi-impl records it against the draft chain's
changelog right AFTER a successful publish (retried up to 3 times), so a
failed publish never leaves an orphan note.

A publish can take a minute or two. Progress lines go to stderr, also with
--llm: `[wi-impl ad publish] validating…`, `publishing…`, `recording the
change note…`. If the client times out, the publish may still complete on
the server: check `wi-impl ad state <uuid>` (inSync, published version)
before publishing again.

The publish also changes what is not in the method body:
  - Test suite: the server REPLACES the published suite with a copy of the
    draft's. The suite and every case get new ids (old published case ids no
    longer exist), and a case only the published copy had is DELETED. wi-impl
    warns before publishing when the published suite has cases the draft
    lacks (back them up with `wi-impl ad test-case export <published uuid>`),
    and reports data.testSuite {previousSuiteId, suiteId, copied[{name,
    draftId, publishedId, previousId?}], removed[{id, name}]}.
  - Removed inputs: an input the published copy has and the draft dropped is
    removed by the platform from every caller step, PUBLISHED callers too
    (they stop passing it until republished). wi-impl warns before publishing
    and lists the caller steps that pass it: data.removedInputs {keys,
    callers[{name, category, state, uuid, step, inputs}], unscannedMethods?,
    error?} (found like `wi-impl ad callers`; a failed lookup never blocks).

Arguments:
  <UUID>                Draft uuid, its PUBLISHED uuid (switched to the linked draft), or an AD URL.

Flags:
  --note "<text>"       The change note recorded against the chain. (required)
  --yes, -y             Skip the confirmation prompt (required with --llm).
  --no-validate         Skip the validator. Logged loudly; not recommended.
  --strict              New validator warnings block the publish too.
  --dry-run-compile     Also run the online checks (server compile dry run).
  --allow-preexisting   Publish even if the current published copy already has
                        the same validator errors (they block by default).
                        A warning the published copy already has never blocks.
  --help, -h            Show this help message.

Global Flags:
  --env <name>          Set active environment. Required: publish is a write.
  --llm                 Output structured JSON envelope for scripting/LLM use.

Safety:
  - A missing --note aborts before any server call (MISSING_CHANGE_NOTE).
  - Validator errors on the draft → AD_VALIDATION_FAILED (details {errors,
    warnings, blocking, layersRun, preexistingCount}); nothing is published.
    Findings also present in the published copy are marked preexisting
    (originalSeverity says what they were); only pre-existing errors block,
    and then the message marks them "(pre-existing)" and names
    --allow-preexisting.
  - After the confirmation the draft is re-read; if it changed since it was
    validated → AD_VERSION_CONFLICT, nothing is published.
  - The change note is POSTed AFTER the publish call, on the draft chain and on
    the published chain (the server copies the draft's changelog onto the
    published copy only when publishing, so a note recorded after it would
    otherwise reach `wi-impl ad changelog <published uuid>` only at the next
    publish, which replaces that list, so there is no duplicate). Both
    changelogs are read back: noteRecorded is true only when the note is in
    both (changelogId / publishedChangelogId, noteChainId /
    publishedNoteChainId). If it is missing the publish stands: the envelope
    is ok with noteRecorded:false, noteError and a warning (with the
    `wi-impl ad changelog` command to re-record when it is not on the draft).
    A note POST that may have reached the server (connection reset or timeout
    after sending) is not re-sent: wi-impl looks for it in the changelog, and
    otherwise says to check `wi-impl ad changelog` before re-recording.
  - After publishing, the compiled cache of the draft and published uuids is
    evicted on both cache routes (data.compiledCache), and the method's own
    cached contract is dropped, so callers' saves see its new inputs at once.
  - Re-fetches both draft and published and reports inSync (logic
    fingerprints equal), noteRecorded, changelogId, testSuite and validation
    warnings.

Examples:
  wi-impl ad publish 4a1b2c3d... --note "Fix null check in step 3" --env <env>
  wi-impl ad publish 4a1b2c3d... --note "Fix null check in step 3" --env <env> --yes --llm
  wi-impl ad publish 4a1b2c3d... --note "Hotfix" --env <env> --allow-preexisting

See also: wi-impl ad changelog — record/list change notes without publishing.
