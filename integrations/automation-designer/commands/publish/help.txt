Usage: belz ad publish <uuid> --note "<what changed>" [flags]

Publish a draft — promotes the current draft contents to the published
version of the same method. Returns the published UUID and a version-sync
summary.

A change note is MANDATORY: belz records it against the draft chain's
changelog right AFTER a successful publish (retried up to 3 times), so a
failed publish never leaves an orphan note. Requires --env (write).

Flags:
  --note "<text>"  Required. The change note recorded against the chain.
  --yes, -y        Skip the interactive confirmation prompt
  --v2             Accepted for consistency; always V1 (a notice is printed)
  --llm            Emit a JSON envelope; --yes is required in this mode

Safety:
  - A missing --note aborts before any server call (MISSING_CHANGE_NOTE).
  - The change note is POSTed AFTER the publish call. If it still fails after
    retries the publish stands: the envelope is ok with noteRecorded:false,
    noteError, and a warning with the `belz ad changelog` command to re-record.
  - Always routes through resolveDraftTarget: if you pass a PUBLISHED UUID
    belz automatically switches to the linked draft before publishing.
  - Re-fetches both draft and published after the publish call and reports
    inSync (logic fingerprints equal), noteRecorded and changelogId.

Examples:
  belz ad publish 4a1b2c3d... --note "Fix null check in step 3" --env <env>
  belz ad publish 4a1b2c3d... --note "Fix null check in step 3" --env <env> --yes --llm

See also: belz ad changelog — record/list change notes without publishing.
