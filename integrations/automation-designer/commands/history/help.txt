Usage: wi-impl ad history [<action>] <uuid> [flags]

Browse and restore previous versions of an AD method. Calls the published
Expertly.Automation.Method.History service methods via the execute endpoint.

Actions:
  list <uuid>                         List all saved versions (`wi-impl ad history
                                      <uuid>` alone means list)
  show <uuid> --version N             Fetch + parse a specific version: metadata
                                      plus the compact view (in/out/vars and one
                                      line per step, like the `ad show` compact view)
                                      --sql / --code add the whole bodies as
                                      `blocks`, the same shape as the `ad show`
                                      compact view
  diff <uuid> --from N --to M         Compare two versions side by side (step
                                      count, kind changes, input changes, and a
                                      line diff of each changed SQL / code / SpEL body)
  restore <uuid> --version N [--yes]  Revert the DRAFT to a previous version

Flags:
  --version <N>    Version number (for show/restore)
  --from <N>       First version (for diff)
  --to <M>         Second version (for diff)
  --full           show: also return the full parsed method (`method`)
  --sql            show: whole SQL bodies in `blocks` [{step, kind, text}]
  --code           show: whole custom-code bodies in `blocks`
  --keep-case-changes
                   restore: keep the test cases the restore brought back
                   (default: the current cases are put back)
  --yes, -y        Skip interactive confirmation (restore; required for --llm mode)
  --llm            Emit a JSON envelope

Notes:
  - 'list' returns metadata only (no full body). Use 'show' to fetch the
    full jsonDefinition at a specific version. Each row's addedWhen is ISO-8601
    UTC (the platform's zone-less text is UTC; it is kept in addedWhenText).
    Data also has updatedOn: when the method was last saved (ISO UTC).
  - A chain with no saved version gives totalVersions 0, historyEmpty: true and
    a note with updatedOn: the platform keeps history only for saves since it
    began recording it (older versions cannot be opened). It is not an error.
  - 'diff' fetches both versions in parallel and compares the steps (in order)
    on their logic: decoded SQL / code / SpEL, called services, mappings,
    conditions. Ids and base64-vs-plain encoding do not count, so an untouched
    step is changed: false. A changed body comes with textDiff: unified-diff
    hunks ("@@ -a,n +b,m @@", then " " context, "-" removed, "+" added lines);
    detail stays "SQL changed" / "Source changed" / "Expression changed" /
    "Step body changed" (something else in the step).
  - The draft and the published chain keep SEPARATE version histories.
    list/show/diff read the history of the chain the uuid names (a draft
    uuid -> draft history, a published uuid -> published history), so the
    same --version N always means the same record in list and show.
  - 'restore' is a write: it requires --env, goes through the draft guard and
    the confirmation gate, and only accepts a DRAFT uuid (a published uuid is
    refused with the draft uuid to use). It calls the
    Expertly.Automation.Method.History.restore internal service, which saves
    the old body as a NEW draft version; wi-impl re-fetches the draft and reports
    resultingVersion and contentMatches. Whatever the platform answers, the
    restore fails (RESTORE_UNCONFIRMED) unless the re-fetched draft verifiably
    carries the target version's content. Content is compared on the
    fingerprint projection (display-only fields such as a method output's
    fieldCode or the category's spelling are ignored); on a mismatch
    data.contentDiff lists up to 10 differing paths. The draft's compiled cache is
    evicted (data.compiledCache) and the restored body is validated
    (data.validation; reported, not blocking — it is already saved).
  - A restore also brings back that version's copy of the test cases, and
    fills every input a case did not set with {}. Test cases are not
    versioned with the method, so wi-impl puts back the cases the draft had
    before the restore. It keeps only the removal of inputs the restored
    version does not declare. Reported as data.testCases {changedByServer,
    restored, failed}. --keep-case-changes reports without restoring.
  - Version numbers are integers starting at 1. Use 'list' to see which
    versions exist.

Examples:
  wi-impl ad history list 4e3f3f8d5f8a8160e879ae012989f6f9
  wi-impl ad history 4e3f3f8d5f8a8160e879ae012989f6f9
  wi-impl ad history show 4e3f3f8d... --version 3 --sql --llm
  wi-impl ad history show 4e3f3f8d... --version 3
  wi-impl ad history diff 4e3f3f8d... --from 1 --to 5
  wi-impl ad history show 4e3f3f8d... --version 1 --full --llm | jq '.data.method.parsedSteps'
  wi-impl ad history restore 4e3f3f8d... --version 3 --env <env> --yes
