Usage: belz ad child-info <CATEGORY> <METHOD-NAME> [flags]

Fetch metadata for a method referenced by name from another method's step
(e.g. when a step calls "Helpers.Legacy.echo" you can look up the child's
inputs/outputs without already knowing its UUID).

Backs GET /rest/api/automation-systems/{category}/automation-apis/{method-name}.
Resolves PUBLISHED methods only.

Arguments:
  <CATEGORY>            Service / category name (e.g. Helpers.JSON, db_service).
  <METHOD-NAME>         Method (automation API) name; db_service uses the uri
                        (select, insert, update, delete, modify).

Flags:
  --shape               Only what wiring a step needs: one line per input
                        (V2 step key path, type, required, BASE_64, enum values,
                        default, UI label), output keys, the automationAPIId /
                        numeric API id, and the service's auth accounts as
                        `id nickname (scope)` (never field values).
  --all                 With --shape: also list inputs/outputs hidden in the UI.
  --help, -h            Show this help message.

Global Flags:
  --env <name>          Set active environment (default: WI_IMPL_ENV, else defaultEnv, else the only env).
                        Any env from `belz envs` (configured in ~/.wi-impl/config.json).
  --llm                 Output structured JSON envelope for scripting/LLM use.

Examples:
  belz ad child-info Helpers.Legacy echo
  belz ad child-info db_service select --shape --llm
  belz ad child-info Helpers.JSON fetchKeyValue --shape
