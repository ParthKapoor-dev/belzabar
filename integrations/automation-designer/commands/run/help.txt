Usage: belz ad run <PUBLISHED_ID> [PAYLOAD] [flags]

Execute a published Automation Designer method. This has real side effects,
so an explicit --env is required.

A uuid runs its OWN saved body: a DRAFT uuid runs the draft (unpublished
changes included), not its published copy. belz warns and reports
inputState/publishedUuid; pass the published uuid to run what is published.

Arguments:
  <PUBLISHED_ID>      The unique ID of the published method version.
  [PAYLOAD]           JSON string or path to a JSON file. Defaults to '{}' if omitted.

Flags:
  --raw               Include raw payload in output.
  --stream            Opt into a streaming method: sends
                      Accept: application/stream+json. If the method streams,
                      progressive chunks are shown and the final JSON envelope
                      is parsed out separately (responseFormat="stream").
                      Non-streaming methods are unaffected.
  --help, -h          Show this help message.

Global Flags:
  --env <name>        Set active environment. Required explicitly: this
                      really executes the chain. Any env from `belz envs`.
  --llm               Output structured JSON envelope for scripting/LLM use.

Notes:
  - Posts the payload to /rest/api/automation/chain/execute/<id>?encrypted=true
    with the raw session token (no Bearer prefix).
  - A non-2xx answer fails EXECUTION_FAILED; details = {path, status, body}
    (the body parsed and redacted).
  - Without --stream the call times out after 10 minutes; with --stream it
    stays open for as long as the method runs.

Examples:
  belz ad run 40ba5566efa95b033ef7af8f7f30ee09 --env <env>
  belz ad run 40ba5566efa95b033ef7af8f7f30ee09 '{"type":"LT262A"}' --env <env>
  belz ad run 40ba5566efa95b033ef7af8f7f30ee09 ./data/payload.json --env <env> --raw --llm
  belz ad run 40ba5566efa95b033ef7af8f7f30ee09 '{"q":"hello"}' --env <env> --stream
