Usage: belz pd diff <input> --from <envA> --to <envB> [flags]

Compare the same page or component across two environments and report the
structural differences: variables (added/removed/changed type or value),
derived fields (from/spec/filterFn/sideEffect), HTTP calls (added/removed/
changed request config), layout nodes (added/removed/changed props, events,
kind), styles, and any other top-level config key.

<input> may be a page/component id, an exact page or component name, an app
URL, or a PD URL. It is resolved INDEPENDENTLY in each environment, because
entity ids are env-local — pass a name or URL when the ids differ.

Flags:
  --from <env>   Environment to treat as the baseline (e.g. acme-dev)
  --to <env>     Environment to compare against (e.g. acme-stage)
  --llm          Emit a JSON envelope

Examples:
  belz pd diff "Vehicle Search" --from acme-dev --to acme-stage
  belz pd diff 49fa2576239ec5791c6ead4cf9408ce2 --from acme-stage --to acme-uat --llm

Notes:
  - Both environments must have valid credentials configured in
    ~/.wi-impl/config.json; a login failure on either side aborts the diff.
  - The diff engine is shared with `belz pd history diff`, so the structural
    comparison is identical — only the two sides differ (envs vs versions).
