Usage: belz pd save <pageId> (--overlay <file> | --config <file>) [flags]

Safe-edit entry point. Applies a validated edit to a PD page draft.

Exactly one of --overlay / --config must be provided.

Flow:
  1. Resolve the draft target via the page's referenceId link. A PUBLISHED
     input writes to its linked draft; a PUBLISHED page with NO draft is
     refused unless --allow-published.
  2. Apply the edit to the current page and validate it. The gate is
     diff-aware: issues the page already had never block; issues the edit
     INTRODUCES do (errors abort unless --force-validation).
  3. Plan the write: partial pageElementOperations when they provably cover
     the whole edit, otherwise a full save (data.fullSaveReason says why).
  4. --dry-run stops here. Otherwise confirm (--yes), acquire the lock,
     re-fetch the page INSIDE the lock, re-apply + re-validate on the latest
     version (data.versionDrift reports a concurrent change), PUT, release.
  5. Read back the page and compare it with the planned config (data.verify:
     match | mismatch | stale-read).

Flags:
  --overlay <file>      Targeted JSON overlay (see OVERLAY SHAPE). Preferred.
  --config <file>       Raw full inner-configuration JSON object (escape
                        hatch). belz stringifies it and sends it with
                        partialUpdate=false.
  --dry-run             Run the full flow but skip the lock and the PUT.
  --force-validation    Proceed despite validator ERRORS (they are listed in
                        data.bypassedErrors). Warnings always just print.
  --allow-published     Allow writing directly to a PUBLISHED page that has
                        no linked draft.
  --force               DEPRECATED alias of --force-validation (it no longer
                        allows writing to a PUBLISHED page). Prints a warning.
  --yes, -y             Confirm the write (required with --llm or without a
                        terminal; otherwise belz asks).
  --help, -h            Show this help message.

OVERLAY SHAPE:
  {
    "variables": {
      "add":    [{"name":"x","type":"String","initialValue":""}],
      "update": [{"name":"x","initialValue":"changed"}],
      "remove": ["old"]
    },
    "derived": {
      "add":    [{"name":"d","from":["x"],"spec":"(function(p){return p.x})"}],
      "update": [{"name":"d","spec":"..."}],
      "remove": ["dead"]
    },
    "httpRequests": {
      "update": [{"callId":"sc-001","request":{"body":"{}"},
                  "handler":{"error":[]},"responseTransformSpec":"..."}],
      "remove": ["sc-dead"]
    },
    "elements": {
      "operations": [
        {"key":"layout.children[0].props.innerHTML","value":"New",
         "operation":"UPDATE","dataType":"STRING"}
      ]
    },
    "nodes": {
      "update": [{"id":"__node_id_1_2_3_4",
                  "props":{"innerHTML":"New","isVisible":null},
                  "field":{"label":"Email"}, "attrs":{}, "events":{}}],
      "insert": [{"parentId":"__node_id_9_8_7_6","index":0,
                  "node":{"name":"span","props":{"innerHTML":"Hi"}}}],
      "remove": ["__node_id_5_5_5_5"]
    },
    "styles": {"replace":".latest-version .x { color: red }"}
  }

  Every name / callId / element key / node id must exist (add: must NOT
  exist), and an unknown top-level section is refused; otherwise the save
  is refused with PD_OVERLAY_INVALID.

  NODES (by id — no children[i] paths; find ids with `belz pd show <page>`
  and its find option): a node is matched by `id`, else `_elementId`; an
  ambiguous id is refused. update MERGES props / field / attrs / events into
  the node (`null` deletes a key; an events entry replaces that event's
  handler list). insert adds `node` under parentId at index (default:
  append); missing ids on the node and its children are generated
  (deterministic, editor format). remove deletes the node and its subtree.
  Order: elements.operations (paths refer to the unedited tree), then
  nodes.update, nodes.insert, nodes.remove. Derived variables
  are the entries with a `from` list (the editor keeps them in
  variables.userDefined) — edit them via "derived", not "variables".

STRATEGY:
  Partial save: variables.update, httpRequests.update (request, handler,
  trigger, triggerFilter, responseTransformSpec), elements.operations,
  nodes.update (keys set at the node's path), styles.replace — with raw
  array indices.
  Full save: variables.add/remove, derived.*, httpRequests.add/remove,
  nodes.insert/remove, a nodes.update that deletes a key (null), legacy-format
  pages, or partial ops that would not cover the edit.
  A full save sends the page's own config with only the edit applied
  (nothing else is rewritten).

Examples:
  belz pd save 4f126300499e4d83cd07a35b4d9af9e7 --overlay ./ed.json --dry-run
  belz pd save 4f126300499e4d83cd07a35b4d9af9e7 --overlay ./ed.json --yes
  belz pd save 4f126300499e4d83cd07a35b4d9af9e7 --config ./full.json --yes
  belz pd save <id> --overlay ./ed.json --force-validation --yes --llm | jq '.data.bypassedErrors'
