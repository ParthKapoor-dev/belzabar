Usage: belz pd show <INPUT> [flags]

Display the structure and metadata of a Page Designer page or component.
The config is fetched and cached automatically. Cached data older than 5
minutes is served instantly while a background process refreshes it
(stale-while-revalidate); use --force to fetch fresh synchronously.

Arguments:
  <INPUT>             One of:
                      • App page URL:  https://<domain>/pages/<path>
                      • PD page URL:   https://.../ui-designer/page/<id>
                      • PD symbol URL: https://.../ui-designer/symbol/<name>
                      • Bare hex ID:   48b75e11e166e6b19e5796d59a936228
                        (page vs. component comes from the server)
                      • Exact component or page name:
                        n_s_staff_email_correspondence, "Add Student"
                        (several matches → PD_NAME_AMBIGUOUS; pass an id)

Output is compact (for agents): with any section flag the summary is just
the identity (name, ids, status, versionId); rows omit empty fields.

Flags:
  --vars              Show all variables (user-defined + derived; derived vars
                      are the entries with a `from` list). Rows: name, type,
                      initialValue (a value over 80 chars JSON becomes
                      initialValueBytes — read it with --var-detail);
                      derived: name, from, sideEffect.
  --http              Show all HTTP service calls. Rows: index, label, callId,
                      adId, triggers, outputs.
  --fields <a,b,…>    Pick the --vars / --http row fields (full values):
                      vars   name,type,initialValue,from,spec,filterFn,sideEffect
                      http   index,label,callId,adId,serviceUuid,method,
                             triggers,outputs,inProgressVar,eventMeta
                      `--fields all` = every field.
  --find <text|id|component>
                      Find layout nodes: an exact id / _elementId, else every
                      node of an exact component name (exp-form-field, button,
                      a symbol name), else a case-insensitive text match on
                      labels, ids and string props. Each match has id,
                      component, kind, label, path (the key path save accepts:
                      elements.operations key = <path>.props.<prop>), parentId
                      and index (for nodes.insert). Prefer editing by id:
                      {"nodes":{"update":[{"id":"<id>","props":{…}}]}}.
  --components        Show the layout tree, one line per node
                      (`<indent>name#id [sym] [ev]`).
  --tree              Show the full layout tree (one line per node) with node-kind badges
                      ([FORM] [TABLE] [BTN] [SYM] [LAYOUT] [-]). Highlights
                      known pitfalls inline (USES-PROPS!, DYN-CLASS!, NO-DS).
  --node <id>         Dump kind-specific detail for a single node by id
                      (field vs props, bindings, validations, event wires).
  --var-graph         Show the per-variable write/read/derive/trigger map.
                      Flags "dead" variables (no writers AND no readers).
  --var-detail <name> Show full config for a specific variable or derived.
  --http-detail <N>   Show full config for the Nth HTTP call (1-indexed).
  --full              Include all sections + all details (the full summary too).
  --recursive, -r     Include the recursive component dependency tree and all
                      AD method IDs (every referenced component is followed;
                      unresolvable ones are listed in recursive.errors).
  --force             Bypass cache and fetch fresh config.
  --raw               Include raw configuration string and source API fields.
  --open, -o          Open the editable draft URL in your default browser
                      (uses the draft id for pages, the component name for
                      symbols).
  --help, -h          Show this help message.

Global Flags:
  --env <name>        Set active environment.
  --llm               Output structured JSON envelope for scripting/LLM use.

Examples:
  belz pd show 48b75e11e166e6b19e5796d59a936228
  belz pd show https://dev.example.test/ui-designer/page/48b75e11e166e6b19e5796d59a936228

  belz pd show 48b75e11e166e6b19e5796d59a936228 --find "Save and Exit"
  belz pd show 48b75e11e166e6b19e5796d59a936228 --find exp-layout-dialog --llm
  belz pd show 48b75e11e166e6b19e5796d59a936228 --http
  belz pd show 48b75e11e166e6b19e5796d59a936228 --components
  belz pd show 48b75e11e166e6b19e5796d59a936228 --var-detail showLoader
