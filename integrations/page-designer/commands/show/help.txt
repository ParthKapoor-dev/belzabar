Usage: wi-impl pd show <INPUT> [flags]

Display the structure and metadata of a Page Designer page or component.
The config is fetched and cached automatically. Cached data older than 5
minutes is served instantly while a background process refreshes it
(stale-while-revalidate); use --force to fetch fresh synchronously.

Arguments:
  <INPUT>             One of:
                      • App page URL:  https://<domain>/pages/<path>
                      • PD page URL:   https://.../ui-designer/page/<id>
                      • PD symbol URL: https://.../ui-designer/symbol/<name>
                      • Bare hex ID:   48b75e11e166e6b19e5796d59a936228
                        (page vs. component comes from the server)
                      • Exact component or page name:
                        n_s_staff_email_correspondence, "Add Student"
                        (several matches → PD_NAME_AMBIGUOUS; pass an id)

Which copy: a NAME resolves to the DRAFT (a notice says so when a published
copy exists); an id or URL reads that row. data.resolvedAs (first key) says
which copy was read: DRAFT or PUBLISHED. --version draft|published reads
that copy instead (the row's referenceId sibling; PD_VERSION_NOT_FOUND when
there is none or it is DELETED). The published row serves the last DEPLOYED
version: after a publish that did not deploy, read the new one with
`wi-impl pd history show <publishedId> --version <vid>`.

Ids are env-local. With --env, an id that is not on that env but is on your
default env is resolved by its NAME on --env (data.byNameFrom, plus a
notice); otherwise pass the name.

Output is compact (for agents): with any section flag the summary is just
the identity (name, ids, status, versionId); rows omit empty fields.

Flags:
  --vars              Show all variables (user-defined + derived; derived vars
                      are the entries with a `from` list). Rows: name, type,
                      initialValue (a value over 80 chars JSON becomes
                      initialValueBytes — read it with --var-detail);
                      derived: name, from, sideEffect.
  --http              Show all HTTP service calls. Rows: index, label, callId,
                      adId, triggers, outputs (variables the success handler
                      writes), errorOutputs (variables the error handler
                      writes: where a failed call's error lands).
  --fields <a,b,…>    Pick the --vars / --http row fields (full values):
                      vars   name,type,initialValue,from,spec,filterFn,sideEffect
                      http   index,label,callId,adId,serviceUuid,method,
                             triggers,outputs,errorOutputs,inProgressVar,
                             eventMeta
                      `--fields all` = every field.
  --find <text|id|component>
                      Search the page. Case-insensitive substring unless noted.
                      find.matches = layout nodes: an exact id / _elementId,
                      else every node of an exact component name
                      (exp-form-field, button, a symbol name), else text in a
                      node's label, id, string props / field / attrs, loop or
                      event handler code. Nodes inside form-builder configs
                      are searched too (match.form). Each node match has id, component,
                      kind, label, path (the key path save accepts:
                      elements.operations key = <path>.props.<prop>), parentId
                      and index (for nodes.insert). Prefer editing by id:
                      {"nodes":{"update":[{"id":"<id>","props":{…}}]}}.
                      find.code = everything outside the layout: variable
                      initial values, derived variable code (spec, filterFn,
                      from) and every field of every HTTP call (callId, label,
                      url, request body, success/error handlers, triggers,
                      triggerFilter, transform code, service-call meta) and
                      form-builder configs outside their node trees. Each
                      code match has where (variable|derived|http|form), name,
                      callId (http), field, line (multi-line values) and the
                      matching text. find.total counts both lists. Not
                      searched: styles.
  --components        Show the layout tree, one line per node
                      (`<indent>name#id [sym] [ev]`).
  --tree              Show the full layout tree (one line per node) with node-kind badges
                      ([FORM] [TABLE] [BTN] [SYM] [LAYOUT] [-]). Highlights
                      known pitfalls inline (USES-PROPS!, DYN-CLASS!, NO-DS).
  --node <id>         Dump kind-specific detail for a single node by id
                      (field vs props, bindings, validations, event wires).
                      Also finds nodes inside form-builder configs
                      (nodeDetail.form names the form variable).
  --var-graph         Show the per-variable write/read/derive/trigger map.
                      Flags "dead" variables (no writers AND no readers).
                      HTTP writers say on: success|error|inProgress. Writers
                      and readers inside form-builder configs count (their
                      entries carry `form`); the form variable itself is a
                      kind: form-config entry read by its builder node.
  --var-detail <name> Show full config for a specific variable or derived,
                      or a form-builder config variable (kind: form-config,
                      the whole form in initialValue, builderNodeIds).

Form builders: an exp-form-builder node keeps its whole form (fields, their
node trees, handlers, [(value)] bindings) in a generated variable named by
its [formConfig] prop, not in the layout tree. --find, --node, --var-graph
and --var-detail read inside it.
  --http-detail <N>   Show full config for the Nth HTTP call (1-indexed).
  --full              Include all sections + all details (the full summary too).
  --recursive, -r     Include the recursive component dependency tree and all
                      AD method IDs (every referenced component is followed;
                      unresolvable ones are listed in recursive.errors).
  --version <draft|published>
                      Read that copy of the page (default: what the input
                      names; a name → the DRAFT).
  --force             Bypass cache and fetch fresh config.
  --raw               Include raw configuration string and source API fields.
  --open, -o          Open the editable draft URL in your default browser
                      (uses the draft id for pages, the component name for
                      symbols).
  --help, -h          Show this help message.

Global Flags:
  --env <name>        Set active environment.
  --llm               Output structured JSON envelope for scripting/LLM use.
