Usage: belz pd analyze <INPUT...> [flags]

Recursively analyze one or more pages/components: every component the layout
references (followed recursively, resolved by name in the active env) and
every AD method their HTTP calls execute.

Arguments:
  <INPUT...>          One or more page/component ids, exact names, or URLs.

Flags:
  --compliance <file> Check the discovered AD ids against a master list file
                      (ids separated by commas and/or whitespace): rogue ids
                      (not in the list), missing ids, common ids.
  --force             Re-read every page/component config (roots and every
                      referenced component) instead of the local cache.
  --help, -h          Show this help message.

Global Flags:
  --env <name>        Set active environment.
  --llm               Output structured JSON envelope for scripting/LLM use.

Notes:
  Components that cannot be fetched or resolved are reported in `errors`
  (and warned about); the rest of the tree is still returned.
  Configs are read from the local cache (up to 1 h old) unless --force;
  data.cache counts cached vs fresh reads, and a warning says when any
  cached config was used.

Examples:
  belz pd analyze 49fa2576239ec5791c6ead4cf9408ce2
  belz pd analyze 49fa2576239ec5791c6ead4cf9408ce2 4de7b4e1d21334bf2d8884b4086d38db
  belz pd analyze 49fa2576239ec5791c6ead4cf9408ce2 --compliance ./master_ids.txt --llm
