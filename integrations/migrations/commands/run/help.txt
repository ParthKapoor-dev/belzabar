Usage: wi-impl migrate run --profile <profile> --module <type> --ids "<csv>" [options]

Trigger a migration build on Jenkins, follow its console, and parse the report.

USAGE
  wi-impl migrate run --profile <profile> --module <type> --ids "<csv>" [options]
  wi-impl migrate run --source-env qa --target-env stage --module AD_Method --ids "<csv>"

REQUIRED
  --module <type>              One of: AD_Method, PD, AD_COMPARISON_REPORT,
                               PD_COMPARISON_REPORT, AD_MIGRATION_STATUS,
                               PD_MIGRATION_STATUS, AD_Service.
                               Use --module-custom for arbitrary values.
                               --module-name is accepted as an alias.

  --profile <name>             A profile name (e.g. devacme_qaacme): a Jenkins
                               PROFILE_NAME choice, <source>_<target>.
  OR
  --source-env / --target-env  Derives the profile through config
                               jenkins.profileEnvs (profile segment → env, e.g.
                               "qaacme": "qa", "stageacme": "stage").

  --ids "<csv>"                Comma-separated UUIDs.
  OR
  --ids-file <path>            File containing IDs (comma/space/newline-separated).

MIGRATION IDS
  Pass either a draft or published id. Before triggering the build, wi-impl
  resolves every id against the SOURCE environment and automatically swaps a
  PD draft for its published sibling (showing the name of each entity being
  migrated) — the migration service itself only accepts published ids, so wi-impl
  does that translation for you. Resolution needs --source-env (or a profile
  whose segments are mapped in jenkins.profileEnvs) plus configured credentials
  for that env. If an id is a draft with no published version, wi-impl aborts
  before the build so nothing is wasted. When resolution can't run (the
  profile's source env isn't in your config, or the profile's envs can't be
  derived), wi-impl WARNS (meta.warnings) and sends the ids as given.

  An AD_Method batch is also checked for members that call each other. The
  service fails a caller whose callee is new on the target ("dependent ... not
  found in destination"), so wi-impl warns, naming each call, and suggests
  waves with callees first (data.batchCalls, data.waves). It does not reorder
  the batch: run one 'migrate run' per wave when a callee is new.

  Every method an AD batch calls is looked up on the TARGET env by
  category/name (needs the target env configured). The service refuses the
  whole batch when one is missing ("dependent method(s) ... not found in the
  destination environment"), so each missing callee is a warning
  (data.calleeCheck.missing [{callee, callers, inBatch}]). Migrate it first, or
  pass --migrate-dependents Y.

  AD drafts are NOT swapped. An AD draft (editor) uuid migrates only the
  draft: the target's PUBLISHED version stays unchanged while the report says
  COMPLETED. wi-impl warns before the build and names the published uuid to
  pass instead. Passing the published uuid copies the source's published
  version AND its draft: the target's draft is overwritten too (the
  confirmation says so).

SAFETY
  - Every run is a real Jenkins build (a --dry-run too), so it is confirmed
    first: a terminal is asked; with --llm or without a terminal --yes is
    required (MIGRATE_CONFIRMATION_REQUIRED, nothing is triggered). The
    prompt / error details list the profile, client, module and resolved ids.
  - --ids and --ids-file cannot be combined (MIGRATE_IDS_CONFLICT).
  - Unknown flags are errors (MIGRATE_UNKNOWN_FLAG, with a did-you-mean), as are
    stray positionals and values on switches (e.g. --dry-run=true).
  - --source-env / --target-env must match the --profile's envs (e.g.
    devacme_qaacme = dev → qa via jenkins.profileEnvs); a contradiction aborts with
    MIGRATE_ENV_PROFILE_MISMATCH. A missing env flag is taken from the
    profile's mapped segment, so --profile alone (or with one env flag) names
    both envs. For a segment that is not mapped, pass both env flags or neither
    (MIGRATE_ENV_PROFILE_UNVERIFIED, details.unmappedSegments; the message
    shows the jenkins.profileEnvs entry to add).
  - --module and --module-custom cannot be combined (MIGRATE_MODULE_CONFLICT).
  - *_COMPARISON_REPORT / *_MIGRATION_STATUS need --migration-id
    (MIGRATE_MIGRATION_ID_REQUIRED).
  - An explicit --client must be the profile's Jenkins client group
    (MIGRATE_CLIENT_PROFILE_MISMATCH).
  - AD ids must be method uuids (32 hex, not all digits:
    MIGRATE_TARGET_ID_INVALID); an unknown one is MIGRATE_TARGET_NOT_FOUND.
    One the source env answers with a DIFFERENT method's uuid is refused
    (MIGRATE_TARGET_ID_MISMATCH, details.resolvedUuid).
  - A PD draft with no published version aborts (MIGRATE_TARGET_DRAFT_UNPUBLISHED);
    any other non-2xx lookup is MIGRATE_TARGET_RESOLVE_FAILED; an unconfigured
    --source-env is MIGRATE_SOURCE_ENV_UNKNOWN. A lookup that times out keeps
    HTTP_TIMEOUT (details.preflightEnv). None of these triggers a build.
  - A profile Jenkins does not list (MIGRATE_PROFILE_NOT_FOUND), or an env
    pair that derives none (MIGRATE_INVALID_ENV_PAIR), names the routes the
    client has, e.g. "ACME has dev→qa, qa→stage, ...; no dev→stage", and a
    two-build path when there is one (details.routes, via, suggestedProfile).
  - Input errors: MIGRATE_PROFILE_REQUIRED / MIGRATE_PROFILE_NOT_FOUND,
    MIGRATE_MODULE_REQUIRED / MIGRATE_INVALID_MODULE, MIGRATE_IDS_REQUIRED /
    MIGRATE_IDS_FILE_NOT_FOUND / MIGRATE_IDS_EMPTY, MIGRATE_INVALID_CLIENT,
    MIGRATE_INVALID_ENV_PAIR, MIGRATE_INVALID_FLAG_VALUE, MIGRATE_UNEXPECTED_ARG.
  - A FAILED entity is MIGRATE_ENTITY_FAILED (see OUTCOME); it may trigger
    one *_MIGRATION_STATUS build to read the reason.
    A declined prompt is MIGRATE_USER_ABORT.
  - Any failure AFTER the build was triggered (queue, console stream,
    timeout) keeps its code and carries details.buildTriggered=true plus
    buildNumber / buildUrl / queueUrl: check it with 'wi-impl migrate status <n>'
    and do NOT re-run (a failed build is MIGRATE_RUN_FAILED; anything else
    after the trigger without its own code is MIGRATE_RUN_INTERRUPTED).

OUTCOME
  A build can finish SUCCESS and change nothing: the migration script skips a
  method whose version is the same on source and target (console "WARNING:
  Method <id> has same version (<n>)", report status UNCHANGED). For a
  followed, non-dry build of ids, data.outcome says what changed:
    MIGRATED          every requested id migrated
    PARTIAL           some ids skipped or UNCHANGED (data.unchanged)
    NOTHING_MIGRATED  every id skipped/UNCHANGED, or no report entity COMPLETED
  Each unchanged id is a warning (meta.warnings). A same-version skip leaves
  the target PUBLISHED as it was, but the target DRAFT may be overwritten:
  bump the source version (publish again) and re-run. data.parsed.skipped and
  data.report.entities (id, name, status, identical) carry the detail.
  The run stays ok (the build succeeded) unless --strict is given.

  FAILED entities fail the run even when Jenkins says SUCCESS:
  MIGRATE_ENTITY_FAILED (MIGRATE_RUN_FAILED when the build failed too), with
  details.failedEntities [{id, name, kind, reason}]. When the console gives no
  reason, wi-impl triggers the job's PD_MIGRATION_STATUS / AD_MIGRATION_STATUS
  build for the migration id and takes the reason from it (details.statusBuild).
  A batch the service refused as a whole is MIGRATE_RUN_FAILED with the
  service's message (details.serviceErrors) and any missing called methods
  (details.missingDependents).

STEP CHECK
  After a successful AD_Method build wi-impl compares each migrated method's
  step inputs on the target with the source (both envs configured). A caller
  can lose step input mappings on the target while the versions say both
  sides are the same; each difference is a warning, and data.stepCheck lists
  them (step, callee, inputs missing / changed / only on the target).

BACKGROUND MODE
  When the migration service answers "Migration running in background (HTTP
  206)", Jenkins reports FAILURE but the ids may still land minutes later. The
  run is not MIGRATE_RUN_FAILED: for AD_Method, wi-impl polls the target env
  (15 s apart, up to 5 min) until each id's published version matches the
  source's. data.background lists landed / notLanded ids per row (source and
  target version); data.outcome is MIGRATED, PARTIAL or NOTHING_MIGRATED from
  that check, each id that did not land is a warning, and only landed ids get
  the target cache clear. Both envs must be known (profile mapping or env
  flags) and configured. Otherwise, and for PD, data.outcome is BACKGROUND:
  check the target yourself before re-running. Progress lines go to stderr in
  every mode (--quiet turns them off).

TARGET CACHE
  After a followed, non-dry AD_Method or PD build whose target env is known
  (--target-env, or the profile via jenkins.profileEnvs), wi-impl drops its
  cached copies of the migrated ids on the target env, so the next
  'wi-impl ad show' / 'wi-impl pd show' there reads fresh (data.cacheInvalidated).
  For AD_Method it also clears the target SERVER's compiled cache for the ids,
  5 rounds 1 s apart (one request reaches one server of a load-balanced env):
  data.serverCache {env, rounds, okRounds, verified}. It needs the target env
  in your config; when it is missing, or a round failed, a warning gives the
  exact 'wi-impl cache' command (5 rounds) to run.

OPTIONS
  --client <name>              Override the client (auto-detected from profile by
                               default). Names are the Jenkins job's client
                               groups (see 'wi-impl migrate profiles'),
                               case-insensitive.
  --migration-id <uuid>        Required for COMPARISON_REPORT / MIGRATION_STATUS.
  --async Y|N                  Run asynchronously. Default: N.
  --migrate-dependents Y|N     Migrate dependent methods/pages. Default: N.
  --devops-tag <ref>           DEVOPS_TAG build parameter (infra branch/tag).
                               Default: develop.
  --dry-run                    NOT a local validation: a real Jenkins build is
                               still triggered, with DRY_RUN=true; the job itself
                               decides what a dry run skips. Argument and id
                               checks happen on every run, dry or not.
  --no-auto-approve            Require manual approval in Jenkins (default
                               sends AUTO_APPROVE=true so we don't get stuck).
  --no-follow                  Trigger build and return without streaming logs.
  --out <path>                 Write summary.json + summary.console.log to dir.
  --quiet                      Suppress progress output.
  --strict                     Fail (exit 1) unless data.outcome is MIGRATED:
                               MIGRATE_NOTHING_MIGRATED or
                               MIGRATE_PARTIALLY_MIGRATED (details.unchanged).
  --yes, -y                    Skip the confirmation prompt (required with --llm
                               or without a terminal).
  --llm                        Emit structured JSON for agent consumption.

CONFIG
  Reads Jenkins credentials from ~/.wi-impl/config.json:
    {
      "jenkins": {
        "baseUrl": "https://jenkins.example.test",
        "user": "<your jenkins user>",
        "password": "<password or API token>",
        "passwordEncoding": "plain",
        "migrationJob": "Folder/db-migration",
        "profileEnvs": { "devacme": "dev", "qaacme": "qa", "stageacme": "stage" }
      }
    }
  Or env vars: WI_IMPL_JENKINS_URL, WI_IMPL_JENKINS_USER, WI_IMPL_JENKINS_PASSWORD,
  WI_IMPL_JENKINS_JOB. migrationJob is required (MIGRATE_JENKINS_CONFIG_MISSING);
  profileEnvs is optional.

EXAMPLES
  # Dry run, qa → stage via jenkins.profileEnvs (still triggers a Jenkins build, DRY_RUN=true)
  wi-impl migrate run --source-env qa --target-env stage \\
    --module AD_Method --ids "<uuid>" --dry-run --yes

  # Real run, explicit profile
  wi-impl migrate run --profile devacme_qaacme --module AD_Method \\
    --ids-file ./ids.txt --async Y --out /tmp/m1

  # Explicit client
  wi-impl migrate run --profile qaacme_stageacme --module AD_Method \\
    --ids "<uuid>" --client ACME --yes --llm
