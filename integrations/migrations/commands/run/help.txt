Usage: belz migrate run --profile <profile> --module <type> --ids "<csv>" [options]

Trigger a migration build on Jenkins, follow its console, and parse the report.

USAGE
  belz migrate run --profile <profile> --module <type> --ids "<csv>" [options]
  belz migrate run --source-env qa --target-env stage --module AD_Method --ids "<csv>"

REQUIRED
  --module <type>              One of: AD_Method, PD, AD_COMPARISON_REPORT,
                               PD_COMPARISON_REPORT, AD_MIGRATION_STATUS,
                               PD_MIGRATION_STATUS, AD_Service.
                               Use --module-custom for arbitrary values.
                               --module-name is accepted as an alias.

  --profile <name>             A profile name (e.g. devacme_qaacme): a Jenkins
                               PROFILE_NAME choice, <source>_<target>.
  OR
  --source-env / --target-env  Derives the profile through config
                               jenkins.profileEnvs (profile segment → env, e.g.
                               "qaacme": "qa", "stageacme": "stage").

  --ids "<csv>"                Comma-separated UUIDs.
  OR
  --ids-file <path>            File containing IDs (comma/space/newline-separated).

MIGRATION IDS
  Pass either a draft or published id. Before triggering the build, belz
  resolves every id against the SOURCE environment and automatically swaps a
  PD draft for its published sibling (showing the name of each entity being
  migrated) — the migration service itself only accepts published ids, so belz
  does that translation for you. Resolution needs --source-env (or a profile
  whose segments are mapped in jenkins.profileEnvs) plus configured credentials
  for that env. If an id is a draft with no published version, belz aborts
  before the build so nothing is wasted. When resolution can't run (the
  profile's source env isn't in your config, or the profile's envs can't be
  derived), belz WARNS (meta.warnings) and sends the ids as given.

SAFETY
  - Every run is a real Jenkins build (a --dry-run too), so it is confirmed
    first: a terminal is asked; with --llm or without a terminal --yes is
    required (MIGRATE_CONFIRMATION_REQUIRED, nothing is triggered). The
    prompt / error details list the profile, client, module and resolved ids.
  - --ids and --ids-file cannot be combined (MIGRATE_IDS_CONFLICT).
  - Unknown flags are errors (MIGRATE_UNKNOWN_FLAG, with a did-you-mean), as are
    stray positionals and values on switches (e.g. --dry-run=true).
  - --source-env / --target-env must match the --profile's envs (e.g.
    devacme_qaacme = dev → qa via jenkins.profileEnvs); a contradiction aborts with
    MIGRATE_ENV_PROFILE_MISMATCH. For a profile whose envs belz can't derive,
    pass both env flags or neither (MIGRATE_ENV_PROFILE_UNVERIFIED).
  - --module and --module-custom cannot be combined (MIGRATE_MODULE_CONFLICT).
  - *_COMPARISON_REPORT / *_MIGRATION_STATUS need --migration-id
    (MIGRATE_MIGRATION_ID_REQUIRED).
  - An explicit --client must be the profile's Jenkins client group
    (MIGRATE_CLIENT_PROFILE_MISMATCH).
  - AD ids must be method uuids (32 hex, not all digits:
    MIGRATE_TARGET_ID_INVALID); an unknown one is MIGRATE_TARGET_NOT_FOUND.
    One the source env answers with a DIFFERENT method's uuid is refused
    (MIGRATE_TARGET_ID_MISMATCH, details.resolvedUuid).
  - A PD draft with no published version aborts (MIGRATE_TARGET_DRAFT_UNPUBLISHED);
    any other non-2xx lookup is MIGRATE_TARGET_RESOLVE_FAILED; an unconfigured
    --source-env is MIGRATE_SOURCE_ENV_UNKNOWN. A lookup that times out keeps
    HTTP_TIMEOUT (details.preflightEnv). None of these triggers a build.
  - Input errors: MIGRATE_PROFILE_REQUIRED / MIGRATE_PROFILE_NOT_FOUND,
    MIGRATE_MODULE_REQUIRED / MIGRATE_INVALID_MODULE, MIGRATE_IDS_REQUIRED /
    MIGRATE_IDS_FILE_NOT_FOUND / MIGRATE_IDS_EMPTY, MIGRATE_INVALID_CLIENT,
    MIGRATE_INVALID_ENV_PAIR, MIGRATE_INVALID_FLAG_VALUE, MIGRATE_UNEXPECTED_ARG.
    A declined prompt is MIGRATE_USER_ABORT.
  - Any failure AFTER the build was triggered (queue, console stream,
    timeout) keeps its code and carries details.buildTriggered=true plus
    buildNumber / buildUrl / queueUrl: check it with 'belz migrate status <n>'
    and do NOT re-run (a failed build is MIGRATE_RUN_FAILED; anything else
    after the trigger without its own code is MIGRATE_RUN_INTERRUPTED).

OPTIONS
  --client <name>              Override the client (auto-detected from profile by
                               default). Names are the Jenkins job's client
                               groups (see 'belz migrate profiles'),
                               case-insensitive.
  --migration-id <uuid>        Required for COMPARISON_REPORT / MIGRATION_STATUS.
  --async Y|N                  Run asynchronously. Default: N.
  --migrate-dependents Y|N     Migrate dependent methods/pages. Default: N.
  --devops-tag <ref>           DEVOPS_TAG build parameter (infra branch/tag).
                               Default: develop.
  --dry-run                    NOT a local validation: a real Jenkins build is
                               still triggered, with DRY_RUN=true; the job itself
                               decides what a dry run skips. Argument and id
                               checks happen on every run, dry or not.
  --no-auto-approve            Require manual approval in Jenkins (default
                               sends AUTO_APPROVE=true so we don't get stuck).
  --no-follow                  Trigger build and return without streaming logs.
  --out <path>                 Write summary.json + summary.console.log to dir.
  --quiet                      Suppress progress output.
  --yes, -y                    Skip the confirmation prompt (required with --llm
                               or without a terminal).
  --llm                        Emit structured JSON for agent consumption.

CONFIG
  Reads Jenkins credentials from ~/.belz/config.json:
    {
      "jenkins": {
        "baseUrl": "https://jenkins.example.test",
        "user": "<your jenkins user>",
        "password": "<password or API token>",
        "passwordEncoding": "plain",
        "migrationJob": "Folder/db-migration",
        "profileEnvs": { "devacme": "dev", "qaacme": "qa", "stageacme": "stage" }
      }
    }
  Or env vars: BELZ_JENKINS_URL, BELZ_JENKINS_USER, BELZ_JENKINS_PASSWORD,
  BELZ_JENKINS_JOB. migrationJob is required (MIGRATE_JENKINS_CONFIG_MISSING);
  profileEnvs is optional.

EXAMPLES
  # Dry run, qa → stage via jenkins.profileEnvs (still triggers a Jenkins build, DRY_RUN=true)
  belz migrate run --source-env qa --target-env stage \\
    --module AD_Method --ids "<uuid>" --dry-run --yes

  # Real run, explicit profile
  belz migrate run --profile devacme_qaacme --module AD_Method \\
    --ids-file ./ids.txt --async Y --out /tmp/m1

  # Explicit client
  belz migrate run --profile qaacme_stageacme --module AD_Method \\
    --ids "<uuid>" --client ACME --yes --llm
