Usage: belz setup [flags]

Interactive first-time setup. Walks you through adding environments (name,
base URL, credentials) and optional Teamwork creds, then writes
~/.wi-impl/config.json. There are no built-in environments.

Passwords are base64-encoded before being stored. The config file is the
source of truth: it overrides any matching environment variables.

Flags:
  --env-file <path>  Load credentials from a .env file instead of prompting.
  --from-env         Load credentials from the current process environment
                     (no prompts, no file) — e.g. inside a CI or cloud session.
                     Values Bun auto-loaded from a .env in the current directory
                     are ignored (and listed as a warning).
  --force            Overwrite an existing config without asking.
  --replace          Drop every configured environment not given in this run
                     (default: merge into the existing config). Needs --force.
  --help, -h         Show this help message.

--env-file and --from-env cannot be combined.

NON-INTERACTIVE KEYS (--env-file / --from-env)
  Environments:       WI_IMPL_ENV_<NAME>_URL, WI_IMPL_ENV_<NAME>_USER,
                      WI_IMPL_ENV_<NAME>_PASSWORD, WI_IMPL_ENV_<NAME>_PROJECT
                      where <NAME> lowercases with `_`→`-`
                      (WI_IMPL_ENV_ACME_QA_URL → env "acme-qa"). URL is required
                      for every env.
  Jenkins:            WI_IMPL_JENKINS_URL, WI_IMPL_JENKINS_USER,
                      WI_IMPL_JENKINS_PASSWORD, WI_IMPL_JENKINS_JOB
  Teamwork:           TEAMWORK_URL, TEAMWORK_EMAIL, TEAMWORK_PASSWORD
  All *_PASSWORD values are plain text (not base64); they are stored with
  "passwordEncoding": "plain" in ~/.wi-impl/config.json (mode 600). Envs you
  don't list are kept; add --replace --force to drop them.

Note: 'belz setup' refuses to run interactively with --llm or on a non-TTY.
Use --env-file or --from-env to populate config non-interactively.

Examples:
  belz setup
  belz setup --env-file ./secrets.env --force
  belz setup --from-env --force          # CI / cloud session
